## Verdict at review time

Claude found the milestone unsafe to advance to a pagination probe. Two findings were blocking:

1. The fetch call used the default redirect behavior. A 307 or 308 could forward the custom `apikey` header and POST body, and one ledger reservation could cause several outbound requests.
2. Reservation counting was a read-then-append operation without a cross-process lock. Claude reproduced a race on a scratch ledger where eight processes starting from four attempts all reserved, leaving twelve attempts against the cap of five.

Claude otherwise found that dry-run was the real default, application/client isolation held, sensitive values were absent from output, pending and unknown charges counted conservatively, and the contract claims were mostly careful.

## Disposition in the offline correction

- Redirect following is disabled with `redirect: "error"`; redirect rejection settles the single reservation as a request error and stops.
- An exclusive no-follow filesystem lock now covers the complete live run. Contention and crash-left locks fail closed before reservation or fetch.
- Argument parsing and the request loop moved into an import-safe runner with injected fetch, paths, key, clocks, sleep, raw writer, and attempt observer.
- Direct offline tests now exercise authentication/credit stops, the two-attempt transient limit, unexpected pricing, redirect rejection, unknown arguments, dry-run non-mutation, malformed pagination, retained-credit caps, ledger ordering, double settlement, credit-header parsing, 3xx handling, key redaction, lock contention, and raw-write accounting.
- The key is parsed only from the canonical repository `.env.local`; shell precedence and unrelated variables no longer apply.
- Ledger, lock, environment, and raw paths derive from the module's repository root. Ledger/lock/raw access rejects symlinks and unsafe paths and uses restrictive permissions.
- Response status and credit headers are captured before raw-response persistence. Signed-zero observed USD values now invalidate the sanitized contract result.
